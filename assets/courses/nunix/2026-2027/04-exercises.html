Exercise 1: filename patterns

List the entries in /usr/bin whose names:

  1. Start with m.
  2. Start with m and have exactly three characters.
  3. Start with m and have at least three characters.
  4. Start with m and have an extension after a dot.

Possible patterns: /usr/bin/m, /usr/bin/m??, /usr/bin/m??, /usr/bin/m.?. ls -d lists the matching entries themselves. ? after the dot requires at least one extension character. With Bash defaults, an unmatched pattern remains literal.

Exercise 2: the initial files

Directory Contains
practice/user1/ f1, f2, f3
practice/user2/ f4

The current directory is practice/user2/.

What relative path names user1's file f1?

Answer: ../user1/f1. user1 and user2 are sibling directories. f1 to f4 may contain any short sample text; the next question specifies f5's contents.

Exercise 2: redirections with cat

Using cat and redirections:

  1. Create f5 containing the line 5 2 3 -1.
  2. Create f6 from f4, followed by f5.
  3. Append user1's f1 to f6.
  4. Copy user1's f2 into a new file f7 in user2.

From practice/user2: cat > f5, enter 5 2 3 -1, press Enter, then Ctrl+D. Next: cat f4 f5 > f6; cat ../user1/f1 >> f6; cat ../user1/f2 > f7.

Exercise 3: a script with three filenames

Write a script named execution, called with n1 n2 n3.

Step Input Program Output
1 File n1 p1 File n1.r1
2 File n2 p1 File n2.r1
3 n2.r1, then n1.r1 p2 File n3

p1 and p2 read stdin and write stdout.
Concatenate the two intermediate files in the stated order.

Assuming p1 and p2 are executable programs in the current directory: ./p1 < "$1" > "$1.r1"; ./p1 < "$2" > "$2.r1"; cat "$2.r1" "$1.r1" | ./p2 > "$3". The second intermediate file comes first in the concatenation.

Exercise 3: resolving the paths

Directory Contains
practice/user1/ file1, file2, p1, p2, execution
practice/user2/ Another file named file2

From practice/user1/, run:

./execution file1 ../user2/file2 fileN

Which files are read? Where do the three output files appear?

Inputs: user1/file1 and user2/file2. Intermediate files: user1/file1.r1 and user2/file2.r1. Final output: user1/fileN. user1/file2 is unused. Creating the second intermediate requires write permission in user2.

Exercise 3: interactive input

Write another version of execution that asks the user for:

  • The first input filename.
  • The second input filename.
  • The output filename.

Keep the same processing steps and concatenation order.

read -r reads each filename. Quoted variable expansions preserve spaces in names. The processing order stays the same.

Exercise 4: script arguments

Write argument, using expr to update a counter.

./argument one two three

Expected output:

3 arguments:
  argument 1 - one
  argument 2 - two
  argument 3 - three

Loop over "$@". Start a counter at 1 and update it with counter=$(expr "$counter" + 1). ./argument "one two" three should report two arguments. The script name is excluded from $#.

Exercise 5: finding a pattern

Write mysearch, called with a pattern and a filename:

./mysearch 'error' application.log

Print either:

  • application.log has the pattern
  • application.log does not have the pattern

Handle an unreadable or missing file as an error.

grep -e "$pattern" -- "$filename" > /dev/null handles a leading hyphen in the pattern or filename. Save $? immediately: 0 means match, 1 means no match and 2 means a GNU grep error. /dev/null discards the matching lines.

Exercise 5: repeated searches

  1. Write mysearch2 filename. Ask for a pattern repeatedly until the user enters end.
  2. Write mysearch3 f1 ... fn. Search the supplied files for each entered pattern.

Where does each loop belong? What happens when input reaches EOF?

The outer loop reads patterns; the inner loop visits filenames. Stop when read fails or the pattern is end. Preserve each filename with quotes and report search errors separately from no matches.

Exercise 6: reading find commands

Explain each command. Identify unnecessary directory visits or ambiguous patterns.

find /var/log -exec grep 'www.athabasca.com' {} \;
find . -name 'rc.conf' -exec chmod o+r {} \;
find /usr/local -type f -name '*.html'

The first command also visits directories, which can produce grep errors. The dots in its pattern are regular-expression wildcards; -type f and grep -F would restrict a literal search to regular files. The second command grants read permission to other users on each match. The third selects regular files ending in .html.

Exercise 6: who handles the redirection?

Analyse this command before running it:

find . -name 'tp2' -exec {} < f_in > {}.out \;
  1. Which program opens f_in and {}.out?
  2. Does find replace {} inside the redirection filename?
  3. How would you give each matching program its own output file?

The calling shell opens f_in and creates or truncates the literal file {}.out once, before find runs. Executed matches inherit those descriptors and share the input position. find substitutes {} in -exec arguments, not in shell redirection filenames. A shell invoked inside -exec can perform a separate redirection for each match.
