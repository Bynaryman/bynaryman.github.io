Why use a script?

Today: find the main error in one log.
Next week: check 200 logs every morning, including when you are away.

A saved script lets the team:

  • Apply the same rule to every input.
  • Review and change the procedure as text.
  • Run it remotely or through a scheduler.
  • Check output and failure status.

The 200-log workload is a hypothetical example. A scheduler can run a saved script each morning; SSH can run commands on a remote machine. A script repeats its mistakes too, so results and exit statuses need checking.

Which tool fits the task?

Task A useful starting point
Explore sales figures, filter and make a chart Excel or another graphical analysis tool
Inspect a server’s logs, processes and permissions Remote shell and system commands
Repeat a file-processing procedure every morning A tested script and a scheduler
Query related business tables SQL and a database
Explain the result to the team A spreadsheet, dashboard or report

Excel also offers Power Query and Office Scripts for repeatable work.

Power Query records transformations that can be refreshed. Office Scripts automates workbook operations. SQL suits queries across related tables. Shell commands give access to the files, processes and permissions of the machine hosting an application.

Unix, GNU and Linux

Name Meaning
Unix The operating-system family that inspired Linux
GNU The project behind Bash and many command-line tools

GNU = GNU’s Not Unix.
The name contains itself: a recursive acronym.

Terminal, shell, command

Name Role
Terminal emulator Displays text and receives keyboard input
Shell Interprets command lines and runs commands
Command Performs an operation, such as listing files

A script saves a sequence of shell commands in a file.

Konsole, GNOME Terminal and xterm are terminal emulators. Bash, zsh, ksh and csh are shells. The account database records the login shell, often in /etc/passwd. The examples use Bash.

A command and its arguments

ls -l /home/alice
Part Role
ls Command name
-l Option: request the long listing format
/home/alice Argument: directory to list

Arguments provide information to a command when it starts.

Getting help

man ls
info coreutils
apropos directory
help cd
  • Tab completes a name or displays possible completions.
  • Up recalls a previous command. history lists history.
  • clear clears the display. In man, q quits.

help documents Bash builtins, including cd. man and info require the corresponding documentation to be installed. In interactive Bash, !! recalls and executes the previous command.

One directory tree

  • The filesystem has a common root: /.
  • Other filesystems appear at mount points in that tree.
  • Each account has a home directory and belongs to groups.
  • Permissions control access to files and directories.

Example home directory: /home/alice
The university may use a different path.

A USB filesystem can be mounted under /media or /mnt. Its device node is under /dev. The mount point gives access to the files stored on the device.

Where Linux stores files

Need Typical location
Alice’s personal files /home/alice
System configuration /etc
Installed add-on applications /opt
Changing application data /var/lib
Log files /var/log

Configuration: /etc · Logs: /var/log

These paths follow common Linux conventions. /var/lib stores persistent application state. Filesystem Hierarchy Standard.

Users, administrators and software

Directory Typical role
/home, /root User homes; the root account’s home
/usr Most distribution-provided tools and libraries
/usr/local Software installed locally by the administrator
/opt Add-on software packages

/ is the filesystem root.
root is also the administrator account’s name.

/root is the root account's home directory, inside the filesystem root /. /usr contains software and shared resources. Ordinary user homes are usually under /home. FHS.

Temporary files and system information

Directory Purpose / lifetime
/var Changing data, often persistent
/tmp Temporary files; cleanup policy varies
/run Runtime state, cleared at boot
/dev Device interfaces
/proc, /sys Views of processes, kernel and devices

A path can expose live system information.
It need not refer to ordinary data stored on disk.

Files in /tmp may be removed at boot or by periodic cleanup. /proc and /sys are virtual filesystems that expose live kernel information. /proc/meminfo, for example, reports memory statistics.

Several filesystems, one tree

/
├── home/       user files
├── mnt/        a temporary mount point
└── media/      removable media mount points

Mounting makes another filesystem visible at a directory.
The device node might be /dev/sdb1; its files appear at the mount point.

/dev/sdb1 names a device partition; /media/alice/USB is an example mount point. Many distributions link /bin and /sbin into /usr. ls -ld /bin /sbin shows whether this is the case on your machine.

The current directory

Notation Meaning
. Current working directory
.. Parent directory
/ Root directory
~ Your home directory, expanded by the shell
$HOME Variable containing your home path
$PWD Variable containing the current directory path

An interactive login commonly starts in the home directory, but a terminal or program can start elsewhere. The directory used to resolve a relative path is the current working directory. Plain ~ means the current user's home; ~alice means Alice's home. ~/alice means a directory named alice inside your own home.

Absolute and relative paths

Path Interpretation

../bob/notes.txt Go to the parent, then into bob

A path tells us where to look. Permissions determine whether access is allowed.

Creating, copying and moving files

touch notes.txt
cp notes.txt notes-copy.txt
mv notes-copy.txt archive.txt
rm archive.txt

touch creates a missing file, or updates timestamps of an existing file.

cp and mv can overwrite an existing destination. cp file directory copies into the directory. cp -r source destination copies a directory tree; mv can also move directories.

Why is less called less?

Mark Nudelman was investigating errors in large logs.
He wanted to read the lines before an error.

His version of more could not move backward.
The new pager’s name joked about a backward more.

less app.log

In less, /ERROR searches for ERROR, n finds the next match, and q quits. Source: Mark Nudelman's FAQ.

Concatenating files

cat first.txt second.txt
cat
  • With filenames, cat prints their contents in argument order.
  • Without filenames, cat reads standard input.
  • At an empty terminal input line, Ctrl+D indicates end of input.

cat first.txt - second.txt reads first.txt, then stdin, then second.txt. Ctrl+D is the terminal's end-of-file input action, not a signal. If characters are pending on a line, the first Ctrl+D submits them instead of producing an empty read. The distinction returns in the process lecture.

Filename patterns

Pattern Matches
? Exactly one character
* Zero or more characters
[abc] One character from the set 
ls /etc/rc*
ls /etc/rc????
ls [abc]oo.c

The shell expands these patterns before running ls.

Examples depend on existing names. With Bash defaults, an unmatched pattern remains literal. A wildcard usually does not match an initial dot, and a slash is a path separator. [abc]oo.c may match aoo.c, boo.c and coo.c. These are filename patterns, also called globs; grep's regular expressions use different rules.

Quoting special characters

Form Effect
\* Treat the next * literally
'*.txt' Preserve every character inside the quotes
"$HOME" Expand the variable, keep the result as one word 
echo *.txt
echo '*.txt'
cat "meeting notes.txt"

Quotes help preserve one argument even when its value contains spaces.

Double quotes allow variable, command and arithmetic expansion. Backslash can escape selected characters. The shell removes its quote characters before passing arguments to the command.

What does the command receive?

In a directory containing only a.txt and meeting notes.txt:

printf '<%s>\n' *.txt
printf '<%s>\n' '*.txt'
<a.txt>
<meeting notes.txt>
<*.txt>

The first glob expands into two arguments. A matched filename containing spaces stays one argument. The quoted pattern stays literal. printf repeats its format for each argument. LC_ALL=C gives the ordering shown here.

3. Who may access this file?

Identify the account, inspect the path, explain the permission check

Users, groups and ownership

whoami
id
ls -ld .
ls -l
  • id shows your user identity and groups.
  • ls -l shows the file’s owner, group and permission bits.
  • ls -ld inspects a directory itself.

These commands show your account and the ownership of files in the current directory.

Permission classes

-rwxr-xr--
  u  g  o
Class Applies to
u The file's owner
g Members of the file's group
o Other users
a All three classes when using chmod

The first character is the entry type: - for a regular file, d for a directory, l for a symbolic link. The next nine characters form the owner, group and other permission classes. The applicable class determines access; the bits from different classes are not added together. ACLs and privileged accounts add further rules.

What r, w and x allow

Bit Regular file Directory
r Read contents List entry names
w Modify contents Add or remove entries*
x Execute Search / traverse

*Changing directory entries also requires search permission. Other restrictions, such as the sticky bit, may apply.

Deleting a filename is an operation on its parent directory. A file's own write bit is not the permission that directly authorises deleting its name. Directory read permission alone does not grant access to the files inside it.

Changing permission bits

chmod u+x script.sh
chmod go-w notes.txt
chmod u=rw,g=r,o= notes.txt
  • + adds the selected permission bits.
  • - removes them.
  • = sets the selected class to the listed permissions.

The owner can normally change a file's permissions. If u, g, o or a is omitted, the umask affects which bits chmod changes.

Numeric permissions

Each class adds its bit values: r = 4, w = 2, x = 1.

Owner Group Others
rwx = 7 rw- = 6 r-- = 4 
chmod 764 notes.txt

The three digits describe owner, group, others, in that order.

“I can see the name, but cannot read it”

# Illustrative server metadata
 drwxr----- alice students  shared/
 -rw-r----- alice students  shared/notes.txt

Bob belongs to students. He can list the names, but cannot open notes.txt. Why?

The directory’s group bits lack x: traversal.
If team access is intended, the owner can add g+x.

The directory lacks group search permission. Its owner can grant it with chmod g+x shared. Bob then has directory traversal and file read access. ls -ld shows the permissions on each directory in the path. The ownership values shown are part of the example.

Path components and word counts

dirname /home/alice/notes.txt
basename /home/alice/notes.txt
wc -w notes.txt
  • dirname prints /home/alice.
  • basename prints notes.txt.
  • wc -w counts words. wc -l counts newline characters.

Hard links and symbolic links

Hard link

ln notes.txt other.txt
  • Another name for the same file.
  • Removing one name leaves the other usable.
  • Same filesystem, normally no directory links.

Symbolic link

ln -s notes.txt shortcut
  • Stores a path to a target.
  • May cross filesystems or target a directory.
  • Can become dangling if the target path disappears.

A relative symbolic-link target is resolved from the directory containing the link. Hard links are equivalent names for the same file.

Builtins and external commands

Builtin

Implemented inside the shell.

cd ..

Can change the current shell's state.

External program

Loaded from an executable file.

ls -l

The shell searches directories in PATH.

PATH commonly includes /usr/bin and other directories. An external cd could only change its own process's working directory. cd must run inside the shell to change that shell's directory. echo and pwd can have both builtin and external implementations.

Recognising a command

type cd
type ls
type -a echo
help cd

type reports how Bash resolves a name.
help documents its builtins.

Aliases and functions can change which command runs. type -a lists all available interpretations of a name.
