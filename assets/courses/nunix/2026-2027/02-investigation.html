Investigating with commands

A computer is slow. Would adding RAM help?
Check which resource is under pressure first.

  1. Check CPU, memory and disk usage.
  2. Find large files and inspect application logs.
  3. Count error codes with a pipeline.

1. Processes and resources

Check CPU, memory and disk usage

CPU, memory and disk space

Resource Question First observation
CPU Is computation keeping a processor busy? top, ps
RAM Is memory pressure affecting the system? free -h
Disk Can the filesystem store more data? df -h .

Adding RAM does not create free space on a full disk.

These commands report your machine's resources. Memory and CPU usage change with the workload, so compare several observations. Linux uses spare memory for caches; free's available column estimates memory available to applications.

Running in the foreground

A process is a running instance of a program.

sleep 10

The shell waits for this foreground command to finish before showing a new prompt.

Ctrl+C requests an interrupt of the foreground job.

Inspecting processes

ps
ps -ef
Field Meaning
PID Process identifier
TTY Associated terminal, if any
TIME Accumulated CPU time
CMD Command

With Linux procps, ps selects processes with the same effective user ID and terminal as the caller. ps -ef lists all processes in full format. TIME is accumulated CPU time. ps -a excludes session leaders and processes without a terminal.

Checking memory usage

free -h
ps -eo pid,comm,%cpu,%mem --sort=-%mem
  • Read available memory; cache use is normal.
  • Identify the application’s process and follow it over time.
  • Check logs before attributing every delay to memory.

ps reports %CPU as a lifetime average and %MEM from resident memory. top refreshes its display; q quits. Shared memory complicates totals. Memory pressure also depends on swap activity and the application's workload.

Checking disk usage

Tool Scope Question
df A filesystem How much space is available?
du A directory tree Which directories use space?
find Individual entries Which files fit my criteria?

Start broad, then inspect a specific file.

du normally measures allocated space. Its total can differ from df because of mount boundaries, filesystem metadata, sparse files or files that were deleted while still open. GNU coreutils: disk usage.

Find which directories use space

df -h "$HOME"
du -h --max-depth=1 "$HOME"

df shows usage of the filesystem containing your home.
du shows how much space your directories use.

GNU du --max-depth=1 shows a total for each immediate subdirectory and for the home directory itself. The totals include files further down the tree.

Finding files

find . -type f -name '*.txt'
  • . is the starting directory.
  • find also visits its subdirectories.
  • -type f selects regular files.
  • -name '*.txt' tests each entry's name.

The quotes let find receive the pattern unchanged.

Search criteria

Criterion Matches
-iname '*.txt' Name, ignoring case
-user alice Entries owned by Alice
-type d / -type l Directories / symbolic links
-size +100M Size greater than 100 MiB
-mtime -2 Modified less than 48 hours ago 
find . -type f -size +100M

GNU find size units: c is bytes, k is 1024-byte units, M is 1048576-byte units. Size is rounded up to the unit before comparison. +100M therefore selects files whose size exceeds 100 MiB. Modification age is counted in completed 24-hour periods: -mtime 2 means at least 48 and less than 72 hours, while -mtime -2 means less than 48 hours. Reference: https://www.gnu.org/software/findutils/manual/html_node/find_html/Age-Ranges.html .

  1. find . -type f -name '*.c'
  2. So the shell passes the pattern to find without expanding it first.

2. Searching text

Read log records and search for errors

A small log file

Save these four lines as app.log:

10:00 INFO STARTED
10:01 ERROR DISK_FULL
10:02 ERROR TIMEOUT
10:03 ERROR DISK_FULL
Field Meaning
1 Time
2 Severity
3 Event code

Each sample record has three fields separated by one space. The cut command below relies on that format. Logs with quoted fields, JSON or multiline records need a suitable parser.

Finding text with grep

grep ' ERROR ' app.log
grep -r ' ERROR ' .
grep -n 'DISK_FULL' app.log
  • Print matching lines from a file.
  • -r searches directories recursively.
  • -n includes line numbers.

Exit status: 0 = match, 1 = no match, 2 = error in GNU grep.

GNU grep returns 0 for a match, 1 for no match and 2 for an error. With -q, a match can produce status 0 even if an error also occurred. GNU grep exit status.

Where the name grep comes from

The editor ed had the command pattern:

g/re/p
  • g: apply globally to matching lines.
  • re: a regular expression.
  • p: print those lines.

grep makes that text search available as a separate command.

Source: GNU grep manual, Introduction.

Patterns in grep

Regular expression Meaning
. Any one character
m* Zero or more repetitions of m
[1-3] A digit from 1 to 3 
grep 'm.*t' names.txt
grep 'toto[1-3]' names.txt

In a regular expression, * repeats the preceding item.

The filename pattern mt and the regular expression m.t use different rules. The regular expression mt also matches a lone t because m allows zero occurrences. Quotes pass the expression to grep without shell expansion.

Who interprets this pattern?

printf '%s\n' *.log
grep 'DISK.*' app.log
find . -name '*.log'
  1. The shell expands a filename pattern.
  2. grep interprets a regular expression.
  3. find interprets a quoted filename pattern.

In a regular expression, * repeats the preceding item. In a filename pattern, * matches zero or more filename characters. Quotes preserve the pattern for grep or find.

Input, output and status

Channel Number Usual terminal behaviour
stdin 0 Read keyboard input
stdout 1 Display normal output
stderr 2 Display diagnostic messages

The exit status is a number reported when a command finishes. It is separate from the text it prints.

The channels are file descriptors. Their destination can be changed by redirection. A filename argument is not itself standard input. Some commands, including cat, recognise a single hyphen argument as a request to read standard input; this is a command convention, not a universal shell rule.

Exit status

true
echo "$?"
false
echo "$?"

0 means success / true. Nonzero means failure / false.
$? is the status of the most recent command.

The example prints 0 then 1. Save status=$? immediately to use it later: even echo changes $?. Nonzero can mean an error or a negative result, such as grep finding no match or diff finding differences.

3. Redirections and pipes

Choose where a command reads and writes

Reading input from a file

sort < names.txt

The shell opens names.txt as standard input for sort.

sort writes the sorted lines to standard output, which still points to the terminal.

sort can also accept a filename argument. With sort < names.txt, the shell opens the file and sort reads its standard input.

Saving output

sort names.txt > sorted.txt
echo 'Zoé' >> sorted.txt
Operator Effect on the destination file
> Create it, or replace its contents
>> Create it, or append to its contents

The shell sets up redirections before running the command. sort names.txt > names.txt would therefore erase the input first. Appending a name leaves it at the end of the file; it does not insert it in sorted order. Sorting depends on the locale.

Redirecting errors

find . -name '*.txt' > matches.txt 2> errors.txt
  • > redirects stdout, descriptor 1.
  • 2> redirects stderr, descriptor 2.
  • Normal results and diagnostics go to separate files.

Redirections are applied from left to right

ls notes.txt missing > all.txt 2>&1
ls notes.txt missing 2>&1 > out.txt
Command stdout ends up… stderr ends up…
First In all.txt In all.txt
Second In out.txt At the terminal

2>&1 copies stdout’s destination at that moment.
It does not make stderr follow later changes to stdout.

Assume notes.txt exists and missing does not. Both commands return nonzero. In the second command, stderr keeps stdout's original destination, normally the terminal. stdout then changes to out.txt. Bash redirections.

Why did the file become empty?

sort names.txt > names.txt

The shell opens and truncates names.txt before starting sort. The input is already gone.

Write to a different file, then inspect the result.

The shell truncates the file before sort reads it. A copy of names.txt can be used to observe this without losing the original contents.

A pipe between two commands

grep ' ERROR ' app.log | wc -l

grep writes matching lines to its standard output.
The pipe connects that output to wc's standard input.

The result is the number of matching lines.

Pipeline processes can run concurrently. They exchange bytes through the pipe. Ordinary | connects stdout only; stderr keeps its own destination. Bash normally runs pipeline elements in separate processes.

Connecting programs like garden hoses

Doug McIlroy described connecting programs so that one program’s output could become another’s input.

grep ' ERROR ' app.log | wc -l

Each tool has a small job.
The shared text stream lets us combine them.

McIlroy proposed the garden-hose analogy in a 1964 memo; Ken Thompson later implemented pipes. Sources: Ritchie's archive, Bell Labs history. The sample command prints 3 for the four-line sample log.

1. Select errors and extract their codes

grep ' ERROR ' app.log |
    cut -d ' ' -f 3
DISK_FULL
TIMEOUT
DISK_FULL

cut -d selects a delimiter and -f selects a field. A trailing pipe continues the command onto the next line. The sample format has exactly one space between fields.

2. Count each error code

grep ' ERROR ' app.log |
    cut -d ' ' -f 3 |
    sort | uniq -c | sort -nr
      2 DISK_FULL
      1 TIMEOUT

uniq -c counts adjacent equal lines. Sort first.

Without the first sort, separated occurrences are counted separately. sort -n compares the counts numerically; -r reverses the order. LC_ALL=C gives the text ordering shown here.

Save and display output with tee

sort names.txt | tee sorted.txt

tee copies its input to a file and standard output.

Think of a T-shaped pipe fitting: the stream has two outlets.

tee writes the same input to stdout and each named file. It overwrites files by default; -a appends.

Combining arguments and redirections

sort < names.txt > sorted.txt
sort < names.txt | head -n 3 > first-three.txt
  • < names.txt selects the input stream.
  • -n 3 remains an argument to head.
  • > first-three.txt selects the output file.

Checkpoint: redirections

  1. Which operator appends to a file?
  2. What does a | b connect?
  3. Does a > out.txt also redirect standard error?
  1. >>
  2. a's stdout to b's stdin.
  3. No. Use 2> to redirect stderr.

The exit status of a pipeline

false | sort
echo "$?"
set -o pipefail
false | sort
echo "$?"

Output: 0, then 1.
Bash normally reports the last pipeline command’s status.

With pipefail, a pipeline returns its rightmost nonzero status, or zero when all commands succeed. This setting alone does not stop the script. grep's no-match status and SIGPIPE from early consumers such as head may need separate handling.

Optional reference

More search expressions and interactive process control

Combining criteria

find /usr -name '*.c'
find . -user alice -name '*.c'
find . -not \( -name '*.obj' -o -name '*.map' \)
  • Adjacent tests use AND. -a makes it explicit.
  • -o means OR. -not negates a test.
  • Escaped parentheses group tests for find.

Running a command on matches

find . -type f -name '*.txt' -exec wc -l {} \;
  • -exec starts the command to run.
  • {} stands for the current matching path.
  • \; ends the command without ending the shell's command line.

This form runs wc once per match. The escaped semicolon belongs to find's -exec syntax. A + terminator can batch several paths into one command call.

Running in the background

sleep 60 &
jobs
fg %1
  • & lets the shell return to the prompt immediately.
  • jobs lists jobs managed by this shell.
  • fg %1 brings job 1 to the foreground.

Job numbers come from the current shell's jobs list. A job can contain several processes. Background jobs can still write to the terminal. With interactive job control, a background job that tries to read the controlling terminal normally stops.

Suspending and resuming a job

Action Effect
Ctrl+Z Suspend the foreground job
bg %1 Resume job 1 in the background
fg %1 Resume job 1 in the foreground

A job number belongs to a shell.
A PID identifies a process in the system.

Sequential and asynchronous execution

who | sort; date
sleep 10 &
date
  • ; runs the next command after the previous one finishes.
  • & starts work asynchronously.
  • The final date can run while sleep is still active.

The semicolon runs the next command after the previous one finishes, whatever its exit status. The background sleep lets the shell continue to date immediately.

Signals and end of input

Action Meaning
kill PID Send SIGTERM to a process
Ctrl+C Send SIGINT to the foreground process group
Ctrl+\ Send SIGQUIT to the foreground process group
Ctrl+Z Send SIGTSTP to suspend the foreground group
Ctrl+D Terminal end-of-input action

PID stands for the process identifier. kill sends a signal; the process may handle or ignore some signals. Ctrl+D requests terminal end-of-input on an empty line. It sends no signal. Signal and key behaviour can depend on handlers and terminal settings.
