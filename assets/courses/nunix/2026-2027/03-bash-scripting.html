1. Scripts, arguments and variables

How can a script use a filename we type or pass as an argument?

A first script

Save these commands in hello.sh:

#!/bin/bash
# A first script
echo "Hello, MIAGE"
  • #!/bin/bash selects Bash for direct execution: the shebang.
  • # begins a comment in this position.
  • Commands run in order. A newline or ; separates them.

The file is plain text. The .sh suffix is a naming convention; the shebang selects the interpreter. Bash means Bourne-Again SHell, a pun on Stephen Bourne's earlier sh. The additional name/history slides are in the reference section for questions, rather than prerequisites for writing a script.

Two ways to run a script

Invoke Bash

bash hello.sh

Bash reads the file.
It needs read access to it.

Execute the file

chmod u+x hello.sh
./hello.sh

Requires execute permission and a usable interpreter.

Both forms require directory traversal and script read permission. Direct execution also requires the execute bit. bash hello.sh selects Bash explicitly; ./hello.sh uses the shebang. Both run in a child process, so their variable assignments do not change the calling shell.

Assigning and reading a variable

filename="app.log"
echo "$filename"
filename="worker.log"
echo "Selected file: $filename"

filename=value stores a value. No spaces around =.
$filename reads that value. Quote it: "$filename".

The output is app.log, then Selected file: worker.log. The assignment changes a variable, not a file. Double quotes preserve a value containing spaces as one argument, as in CM1.

Asking the user with read

read -r -p "File to inspect: " filename
echo "Selected file: $filename"

Type app.log, then press Enter. The message becomes Selected file: app.log.

  • read stores the typed line in filename.
  • -p supplies the prompt displayed before the input.
  • -r keeps backslashes as ordinary characters.

Budget about 2 minutes, including asking which value filename contains before and after read. This prepares interactive filenames in TD3 and repeated user input in TD5 and TP5. With one variable, spaces inside the line remain in its value; leading/trailing separator whitespace is normally trimmed. Exact whitespace handling is in the reference file-reading example.

Positional parameters

A script uses these parameters to read its arguments:

bash arguments.sh "L3 MIAGE" Unix
Parameter Meaning Value for this call
$0 Script name arguments.sh
$1 First argument L3 MIAGE
$2 Second argument Unix
$# Number of arguments 2
"$@" All arguments separately "L3 MIAGE" "Unix"
"$*" All arguments as one string "L3 MIAGE Unix"

$0 is arguments.sh, not bash: it names the script being interpreted. The quotation marks in the last two table rows show the grouping of the values; they are not characters in those values. With the default IFS, "$" joins the arguments with spaces. The next slide demonstrates the difference between "$@" and "$". Use braces from the tenth argument onward: ${10}.

Passing arguments with spaces

Use the same script call:

bash arguments.sh "L3 MIAGE" Unix

Inside the script, printf uses %s for a string and \n for a newline.
It repeats the format for each argument.

"$@": two arguments

printf '<%s>\n' "$@"
<L3 MIAGE>
<Unix>

"$*": one string

printf '<%s>\n' "$*"
<L3 MIAGE Unix>

Use "$@" to pass each argument on unchanged.

Save the two printf commands in arguments.sh, then run the invocation shown above. %s prints a string and \n ends the line. printf repeats the format for each argument. With the default IFS, "$*" joins the arguments with spaces. "$@" keeps them separate.

Saving a command's output

From the extracted TP files:

cd ~/NUnix/files
tpfiles=$(pwd)
cd ..
ls "$tpfiles"

Bash runs pwd and stores its printed path in tpfiles.
That absolute path still works after cd ...

Prepare the TP files before running this example. The TP downloads them into ~/NUnix/files. $(command) captures standard output and removes trailing newlines. It does not capture error messages. The variable remains an ordinary shell variable until exported on the next slides.

Running commands in another Bash

bash -c 'echo "Hello from another Bash"'
  • -c tells Bash to execute the following text as commands.
  • The current shell starts a child Bash, then waits for it to finish.
  • Single quotes pass the text unchanged for that child to interpret.

bash script.sh reads commands from a file.
bash -c 'commands' reads them from the next argument.

Sharing a variable with a script

tpfiles="$HOME/NUnix/files"
export tpfiles
bash -c 'echo "$tpfiles"'
  • The assignment stores the path in the current shell.
  • export includes it in the environment passed to newly started programs.
  • The child Bash can now print the same path.

A child receives a copy. Changing it does not change the parent's variable.

This is the environment-variable operation used in TP3. A script launched from this terminal can use $tpfiles. Export is not needed merely to expand $tpfiles in the current shell. The single quotes make the child, rather than the parent, expand $tpfiles in this command. Use the reference slide A child receives a copy if students ask to see the copy behaviour.

2. Tests and decisions

Before reading a file, how can a script check that it exists and is readable?

Testing a condition

Does the directory logs exist? These two commands ask the same question:

test -d logs
[ -d logs ]

-d means is a directory. [ ... ] is another way to write test.

A test returns a status; it prints no answer.
0: the condition is true. 1: the condition is false.

If logs is a directory, either command returns status 0; otherwise it returns 1. A malformed test can return another nonzero status. The final ] is required by the [ command.

Comparing integers

Compare integers with these operators inside [ ... ]:

Operator Read it as Mathematical symbol
-eq Equal to =
-ne Not equal to ≠
-lt Less than <
-le Less than or equal to ≤
-gt Greater than >
-ge Greater than or equal to ≥

Read [ "$count" -gt 10 ] as count is greater than 10.

Testing text

An interactive script can stop when the user types end.

Test True when...
[ "$answer" = "end" ] The answer is end
[ "$answer" != "end" ] The answer is different from end
[ -z "$answer" ] The answer is empty
[ -n "$answer" ] The answer is not empty

Use = for text and -eq for integer comparisons.

answer is the value obtained from read. The tests themselves do not print anything. Keep the quotes even for an empty answer, so it is still passed as one argument.

Testing files and permissions

A script can check a path before using it:

Test True when...
[ -e "$filename" ] The path exists
[ -f "$filename" ] It is a regular file
[ -d "$filename" ] It is a directory
[ -r "$filename" ] Reading is allowed
[ -w "$filename" ] Writing is allowed
[ -x "$filename" ] Executing / directory traversal is allowed

These are the existence and access checks needed in TP5. Each test reports status 0 or 1. Tests generally follow symbolic links. A directory can pass -r; combine -f and -r to ask for a readable regular file.

if and else

count=12
if [ "$count" -gt 10 ]; then
    echo "More than ten"
else
    echo "Ten or fewer"
fi

A true test runs the then branch; a false test runs else. fi marks the end.

Spaces are required after [ and before ].
Correct: [ "$count" -gt 10 ]
Incorrect: ["$count" -gt 10]

The output is More than ten. [ is a command: spaces separate its name, arguments and closing ]. Keep the spaces after [ and before ], including inside an if. Quote the value of count.

More than two cases: elif

count=10
if [ "$count" -gt 10 ]; then
    echo "More than ten"
elif [ "$count" -eq 10 ]; then
    echo "Exactly ten"
else
    echo "Fewer than ten"
fi

elif means else if. Try each test in order and run the first true branch.
Here, the output is Exactly ten.

If neither condition is true, the else branch runs. A newline can replace the semicolon before then.

Conditional command lists

mkdir results && echo "Directory created"
test -d results || echo "Directory is missing"
  • a && b: run b only when a succeeds.
  • a || b: run b only when a fails.
  • ! a: invert the success/failure result.

A command list returns the status of its last executed command. && and || have equal precedence and are evaluated left to right. Separate [ ... ] commands can be joined with these operators.

Three conditions with &&

Example call: bash check.sh report.log ERROR 10

if [ "$#" -gt 2 ] &&
   [ -f "$1" ] &&
   [[ "$1" == report* ]]; then
    echo "Inputs accepted"
fi
  1. At least three arguments.
  2. $1 names an existing regular file.
  3. $1 starts with report.

[[ ... ]] supports patterns in Bash. Keep report* unquoted.
&& means AND: stop checking as soon as one condition is false.

Allow 2 minutes including a prediction. Prepare report.log and notes.log in the current directory. Save the code in check.sh and run bash check.sh report.log ERROR 10: Inputs accepted. Try only two arguments, a missing report file, and an existing notes.log: nothing is printed. The first failed condition skips the remaining tests and the then branch. A newline after && continues the command list without a backslash. report* is a shell pattern, not a regular expression: the star matches any suffix, including an empty one. Quoting "report" would test that literal text. This tests the argument as written: ./report.log starts with ./, so it does not match report.

Checking the script's arguments

Save as count-lines.sh:

#!/bin/bash
if [ "$#" -ne 1 ]; then
    echo "Usage: $0 FILE" >&2
    exit 2
fi
wc -l < "$1"
  • $# is the argument count; -ne 1 means not equal to 1.
  • >&2 sends the message to standard error.
  • exit 2 stops the script with a nonzero status.

Run bash count-lines.sh names.txt, then run it with no argument. The guard must run before $1 is used. This first check handles the number of arguments; the report example later also checks file access. Status 2 is the convention chosen here for incorrect usage; it is not a truth value to print.

case selects a matching pattern

read -r -p "Enter a command: " choice
case "$choice" in
    all|ALL)
        ls -la ;;
    list|LIST)
        ls -l ;;
    *)
        echo "Invalid choice" ;;
esac

| separates alternative patterns; ;; ends a branch.
*) handles any other answer; esac ends the selection.

case uses shell patterns. The first matching branch runs. all|ALL matches those two spellings; mixed-case All reaches the final * branch.

3. Loops and counters

How can we process several files, or ask again until the user types end?

Calculating with integers

count=3
echo "$((count + 2))"
echo "$count"
5
3

Bash replaces $((count + 2)) with 5 before running echo.
The calculation gives 5; count still contains 3.

No decimal part: $((5 / 2)) gives 2.

Updating a counter

count=3
count=$((count + 1))
echo "$count"

$((count + 1)) calculates 4; the assignment stores it in count.

The TD also uses expr, which prints a calculation's result:

count=$(expr "$count" + 1)

$(...) captures that result. Here, count becomes 5.

Ask for the values after each assignment. expr takes separate arguments: preserve spaces around +. The earlier command-output slide explains $(...). This prepares the counter in TD4 without introducing an unrelated parameter-setting command. The additional let/expr reference includes multiplication.

for visits a list of words

for group in L3info L3miage M1info; do
    echo "$group"
done

Each iteration assigns the next word to group, then runs the body.

The list can contain literal words, numbers, filenames or "$@".

The words can come from a literal list, "$@", or a pattern such as ./*.txt. With Bash defaults, an unmatched pattern remains literal. Parsing ls output with command substitution can split filenames containing whitespace.

One iteration per script argument

In show-files.sh:

for filename in "$@"; do
    echo "File: $filename"
done

Run it with:

bash show-files.sh notes.txt "meeting notes.txt"

Two iterations. "$@" keeps meeting notes.txt as one filename.

Allow one minute for students to predict the number of iterations before revealing the answer. The loop prints the arguments; it does not need these files to exist. This prepares TD4/5 and processing several logs in the guided build.

while repeats after a successful test

i=1
while [ "$i" -lt 10 ]; do
    echo "$i"
    i=$((i + 1))
done

Test before each iteration.
The loop prints the integers 1 through 9.

The condition is a command list. A zero status runs the body; a nonzero status ends the loop. Bash looping constructs.

Asking again until the user stops

read -r -p "Word (end to stop): " word
while [ "$word" != "end" ]; do
    echo "You entered: $word"
    read -r -p "Word (end to stop): " word
done

end makes the test false and stops the loop.
The last read updates word before the next test.

Allow about 3 minutes including a live run with ERROR, TIMEOUT, end. Ask what happens if the second read is removed: the same word is tested forever. This is the interaction pattern in TD5 and TP5; TP5 uses the value 0 to stop. This demonstration assumes the user completes input with end.

while can test a whole command list

i=1
while
    echo "Checking i=$i"
    [ "$i" -le 3 ]
do
    echo "Body: $i"
    i=$((i + 1))
done

The last command before do decides whether the body runs.

A condition list can span several lines. Each command runs in order; the last command's status determines whether the loop body runs. Bash looping constructs.

The condition runs once more than the body

Checking i=1
Body: 1
Checking i=2
Body: 2
Checking i=3
Body: 3
Checking i=4
  • At 1, 2, 3, the test succeeds.
  • At 4, the final test fails.
  • The body does not run a fourth time.

If echo followed [ ... ] in the condition list, echo's usual success status would replace the test's status. This loop would then keep running.

4. Functions

How can we reuse a file-processing step for several files?

Defining and calling a function

Define the function, then call it with a filename:

count_lines() {
    local filename="$1"
    wc -l < "$filename"
}
count_lines "names.txt"
  • Inside the function, $1 is the argument passed to this call.
  • local gives the function its own filename variable.
  • The result is printed on standard output, ready for a redirection or pipe.

names.txt is the three-line input from CM2, so this call prints 3. It must exist before running. Functions run in the current shell, unlike the bash -c child examples. Local variables keep the function's temporary names from changing variables of the caller. return n ends a function with status n; it does not print a result. The reference scope example expands on this distinction.

5. Build a log report

Support has several logs. Can one script count matching lines in each and save a report?

The task and the files

Support checks a web service and an overnight job. Count lines matching a pattern in each log. Save the summary in search-report.txt.

Download the example files, extract them and open report.sh in report-demo.

bash report.sh web.log "worker night.log"
  • Ask for a pattern, such as ERROR.
  • Check the arguments and file access.
  • Process each file, then save its count.

Start the guided build at about minute 60; allow 23 minutes for editing, predictions and a final run. Use the first 2 minutes to read the task and inspect the two logs. The ZIP contains two small logs and a one-line starter report.sh. Work inside its report-demo folder. The completed script is linked on the final slide. It uses the same arguments, read, file tests, functions, loops and redirections needed in TD3–5 and TP5/7 without solving their exercises. Each script-build slide reveals one code line at a time in HTML; the PDF shows all lines.

1. Check that files were supplied

Start report.sh with:

#!/bin/bash
if [ "$#" -eq 0 ]; then
    echo "Usage: $0 LOGFILE..." >&2
    exit 1
fi

Predict: what happens with bash report.sh and no filename?

The script prints its usage on stderr and stops with status 1.

About 2 minutes. Ask students which special parameter counts arguments, and why the guard precedes any use of a filename. Run once with no arguments and once with the two provided logs.

2. Ask what to search for

Add after the argument check:

read -r -p "Pattern to count: " pattern
echo "Searching for: $pattern"

Run the script with the two logs and type ERROR.

read fills pattern. Its value will be reused for every file.

About 2 minutes. Ask which characters belong to the prompt and which become the variable's value. This is a grep regular expression, using the rules from CM2. Use ERROR, WARN or FATAL in the demo. An empty pattern is valid for grep and matches every line; discuss this only if someone tries it.

3. Process one file

Add a function, then call it on the first filename:

report_file() {
    local matches
    matches=$(grep "$pattern" "$1" | wc -l)
    echo "$1: $matches matching lines"
}
report_file "$1"

grep selects the lines; wc -l counts them.
$(...) stores that count in the function's local variable.

About 4 minutes. Ask whose $1 is used inside report_file: the argument of that function call. With ERROR and web.log, the count is 3. No matching line produces a count of 0. The pipeline's status is that of wc by default, so a normal grep no-match result does not abort it.

4. Check and process every file

Replace the single function call with this loop:

for logfile in "$@"; do
    if [ -f "$logfile" ] && [ -r "$logfile" ]; then
        report_file "$logfile"
    else
        echo "Cannot read file: $logfile" >&2
        exit 1
    fi
done

Predict: does worker night.log cause one iteration or two?

About 5 minutes including running it and trying missing.log. "$@" keeps each filename intact. -f checks for a regular file and -r checks read access; both must succeed. An invalid input stops the script at that file. Earlier files may already have been processed.

5. Save the report

Before the loop, create the report and write its heading:

report="search-report.txt"
echo "Matching lines for: $pattern" > "$report"

Inside the loop, redirect the function's output:

report_file "$logfile" >> "$report"

Why >> here? Each file's result must be added after the previous one.

After the loop: echo "Report saved in $report".

About 4 minutes. Ask what > inside the loop would do: only the last file's result would remain. The final echo goes after done. Each run replaces search-report.txt; the demo inputs are the two separate .log files. The function's error messages still go to the terminal. If a later input fails validation, the report contains only earlier successful results.

6. Run it and inspect the result

bash report.sh web.log "worker night.log"

Type ERROR, then run cat search-report.txt:

Matching lines for: ERROR
web.log: 3 matching lines
worker night.log: 2 matching lines

Try WARN, FATAL, a missing file and a call with no arguments.
Complete script

CM3 summary: writing a script

  1. Get inputs with read or the script's arguments.
  2. Store values, quote them and check the inputs.
  3. Use tests and loops to decide what to repeat.
  4. Put a reusable task in a function.
  5. Run the script with normal and incorrect inputs; inspect its output.

Further examples and TP tools

Reference for the TD/TP: extra Bash forms, worked examples and text-editing tools

Options for the TP script

bash main.sh -p samples -h

Bash passes these as ordinary arguments. The script interprets them
with getopts "hp:" option, reading one option at a time:

Item Meaning
h Accept -h without a value
p: Accept -p with a required value
option Variable receiving the option letter
OPTARG Variable receiving its value, here samples

Reading options with getopts

directory="."
while getopts "hp:" option; do
    case "$option" in
        h) echo "Usage: $0 [-p DIRECTORY]"; exit 0 ;;
        p) directory="$OPTARG" ;;
        *) exit 1 ;;
    esac
done
echo "Selected directory: $directory"

The loop runs while another option is available.
An unknown option or a missing value reaches the *) branch.

Save in main.sh. Run bash main.sh -p samples: prints Selected directory: samples. Run with -h: prints help and stops successfully. getopts reports errors on stderr and gives option the value ? in this form, handled by the wildcard branch. This introduces the tool used by the TP7 correction; students still choose their own option names and implement the replacement.

Removing arguments already handled

After bash inspect.sh -p logs app.log, the script can do:

directory="$2"
shift 2
echo "$directory"
echo "$1"

Output: logs, then app.log.
shift 2 removes the first two arguments and renumbers the remaining ones.

After getopts, OPTIND is the position of the next argument.
shift "$((OPTIND - 1))" removes the arguments it has read.

The first example uses the exact call shown. In a general script, validate options and their values before using them, or use getopts.

Replacing text with sed

For a file containing cat cat:

sed 's/cat/dog/' animals.txt
sed 's/cat/dog/g' animals.txt

Output: dog cat, then dog dog.

  • s/old/new/ replaces the first match on each line.
  • The final g replaces every match on each line.
  • These commands print the result and leave the file unchanged.

sed -i 's/cat/dog/g' animals.txt changes the file itself.
Practise on copies.

Use simple words for the first version: the search part is a regular expression, and /, & and backslashes have special roles in sed expressions. The TP correction specifies simple words. GNU sed is used in this Linux course. find -exec, explained in CM2's reference, applies a command recursively; combine the tools only after checking the replacement on one file.

Bash: Bourne again

Bash = Bourne-Again SHell.

The name puns on Stephen Bourne, author of the earlier Unix shell sh.

We use Bash syntax in this course.
sh script.sh may select a different shell with fewer features.

Bourne's shell appeared in Seventh Edition Unix. Bash extends that shell's language. Source: GNU Bash, What is Bash?.

The shebang: selecting an interpreter

#!/bin/bash
printf 'Hello, MIAGE\n'

On Linux, direct execution of ./hello.sh uses the interpreter named after #!.

The extension .sh does not choose Bash.
The first line does. We call it the shebang.

#! must be the first two bytes of the file. Windows CRLF line endings can add a carriage return to the interpreter path and cause an execution error. /usr/bin/env bash is another convention: it searches PATH for Bash. Linux execve: interpreter scripts.

One symbol, several names

Symbol Names you may hear
# hash, number sign; pound sign in US usage
# French: croisillon, also carré
♯ The musical sharp sign (dièse)

#!: hash followed by bang.
The symbol’s name and its role depend on context.

The OQLF lists croisillon and carré for # and distinguishes it from the musical sharp sign ♯. Carré is common in telephone instructions. OQLF: croisillon. In Bash, # at the start of an unquoted word introduces a comment; a # inside ordinary text need not do so.

Quoted variable expansions

filename="meeting notes.txt"
cat "$filename"
echo '${filename}'
echo "${filename}"
  • Double quotes preserve the expanded value as one argument.
  • Single quotes preserve the literal text ${filename}.

cat receives one filename argument. Without quotes, variable expansion normally allows word splitting and filename expansion. The first echo prints the literal ${filename}; the second prints meeting notes.txt.

Printing values

name="Alice"
echo "Hello, $name"
printf 'Hello, %s\n' "$name"

echo is convenient for simple messages.
printf gives explicit control over formatting and newlines.

printf '%s' "$value" prints the value as data, even if it resembles an echo option. The format string controls conversion and newlines.

A child receives a copy

export message="parent"
bash -c 'message="child"; echo "$message"'
echo "$message"
child
parent

Changes in the child do not update the parent's variables. env and printenv show environment variables. Bash's set also shows unexported shell variables and functions.

The condition can be grep

if grep ' ERROR ' app.log; then
    echo "At least one error was found"
else
    echo "No match, or grep could not read the file"
fi

if runs then when the command returns status 0.
Any other status selects else. Here, grep succeeds when it finds a matching line.

grep prints matching lines before the success message. An error also produces a nonzero status, so the else branch covers both no-match and failure.

Which messages appear?

true  || echo "A"
false || echo "B"
true  && echo "C"
false && echo "D"
B
C

Checkpoint: command status

  1. Status 0: true or false?
  2. Does false; echo yes print?
  3. Does false && echo yes print?
  4. Status of false || true?
  1. True / success.
  2. Yes. ; always continues.
  3. No.
  4. 0, from the final executed command, true.

In a && b || c, c runs if a fails or if b fails. This can differ from an if/else statement.

Read a file line by line

while IFS= read -r name; do
    printf 'Hello, %s\n' "$name"
done < names.txt
  • IFS= disables trimming of leading/trailing spaces for this read.
  • -r keeps backslashes unchanged, as in the earlier prompt.
  • read succeeds for each complete line; at EOF, it fails and the loop stops.
  • < names.txt supplies input to the whole loop.

names.txt contains one name per line, with a newline after each name. IFS= preserves leading and trailing whitespace; -r preserves backslashes. To also process a final line without a newline, use while IFS= read -r name || [ -n "$name" ]; do ...; done. File redirection keeps this loop in the current shell.

until repeats after a failed test

i=1
until [ "$i" -ge 10 ]; do
    echo "$i"
    i=$((i + 1))
done

This also prints 1 through 9.
The loop stops when the condition succeeds.

until tests before entering the body, so the body may run zero times. It continues while the condition returns nonzero. Bash looping constructs.

break, continue and exit

Command Effect
continue Skip the rest of the current iteration
break Leave the current loop
exit n End the script with status n

After break, execution continues after the loop.

break and continue can take a nesting level. exit ends the shell running the command; here that shell is executing a script.

Command substitution

echo "Current directory: $(pwd)"

The shell runs pwd and replaces $(pwd) with its standard output.

The older form is `pwd`.
We will write $(pwd) because nested commands are easier to read.

Command substitution captures stdout and removes trailing newlines. stderr and the exit status are separate.

Newlines, semicolons and continuations

echo "first"
echo "second"; echo "third"
echo "a longer message" \
     "continued on the next line"
  • A newline or ; separates commands.
  • A backslash immediately before a newline continues the line.

The continuation backslash must immediately precede the newline. Bash also accepts line breaks after operators such as | and inside compound commands. echo prints its arguments separated by spaces.

Integer, readonly and array variables

declare -i count=3
readonly course="NUnix"
declare -a words
words[0]="one"
words[1]="two"
echo "${words[0]}"

unset count removes a variable. A readonly variable cannot be reassigned or unset in that shell.

declare -i and indexed arrays are Bash features. Arithmetic expansion does not require declare -i. A readonly variable remains readonly until its shell exits; run this example in a fresh Bash shell.

Arithmetic with let and expr

let 'count = 3 + 5'
echo "$count"
expr 3 + 5
expr 3 \* 5
  • let evaluates an arithmetic expression in Bash.
  • expr takes separate arguments, so its spaces matter.
  • Escape * so the shell passes it to expr literally.

The outputs are 8, 8 and 15. A quoted let expression can contain spaces. expr receives the operator and operands as separate arguments, prints its result and returns a status.

Bash arithmetic shortcut: (( ... ))

count=3
((count = count + 1))
echo "$count"
4

((count = count + 1)) tells Bash to calculate and update count.
It prints nothing; echo displays the new value.

Here, it does the same update as count=$((count + 1)).

The double-parenthesis command is a Bash feature. It also returns a status: 0 when the expression's value is nonzero, 1 when its value is zero. This is separate from the value itself.

Bash tests with double brackets

filename="report.txt"
if [[ "$filename" == *.txt ]]; then
    echo "Text file"
fi

[[ ... ]] is another form of test available in Bash.
Here, == *.txt checks whether the name ends in .txt.

With [ ... ], string equality compares literal text; this Bash form also accepts patterns.

Spaces are still required: [[ condition ]].

The pattern on the right of == is intentionally unquoted. Quoting it makes the comparison literal. This example prints Text file. [[ ... ]] is not part of POSIX sh.

Checking access to a file

#!/bin/bash
read -r -p "Enter a filename: " filename
if [ ! -w "$filename" ]; then
    echo "File is not writable"
    exit 1
elif [ ! -r "$filename" ]; then
    echo "File is not readable"
    exit 1
else
    echo "File is writable and readable"
fi

! negates a test. -w checks writing; -r checks reading.

A directory can also pass -r, -w and -x tests. Use -f when a regular file is required. A failed access test may also mean that the path does not exist.

Comparing two files

diff "$1" "$2" > diff.out
status=$?
if [ "$status" -eq 0 ]; then
    echo "Files are identical"
elif [ "$status" -eq 1 ]; then
    cat diff.out
else
    echo "Comparison failed" >&2
fi
rm -f diff.out

status=$? saves the previous command's status. For diff:
0: identical; 1: different; greater than 1: error.

Supply two filenames. diff returns 0 for identical files, 1 for differences and greater than 1 for an error. This example overwrites diff.out in the current directory. A reusable script should use a unique temporary file and arrange cleanup.

Copying a known list of files

#!/bin/bash
destination=$1
for file in f1 f2 f3; do
    cp "$file" "$destination/$file"
done

Call with an existing destination directory as the first argument.

Create f1, f2 and f3 first, then supply an existing destination directory as the script's first argument. Quoting keeps a destination with spaces in one argument.

A loop can feed a pipeline

for number in 6 3 1 2; do
    echo "$number"
done | sort -n
1
2
3
6

The loop's entire stdout feeds sort -n. With normal Bash pipeline execution, variable assignments inside a pipeline element do not update the parent shell.

Repeating until interrupted

while true; do
    echo "alive..."
    sleep 3
done

true always succeeds.
Use Ctrl+C to interrupt this foreground loop.

sleep 3 waits three seconds between iterations. The loop keeps running until interrupted.

Skipping 4, stopping at 7

for x in 1 2 3 4 5 6 7 8 9; do
    if [ "$x" -eq 4 ]; then
        continue
    fi
    echo "$x"
    if [ "$x" -eq 7 ]; then
        break
    fi
done
echo "After the loop: x=$x"

continue skips the print at 4. At 7, the print runs before break. The final echo runs after the loop.

Function scope

label="outside"
show_label() {
    local label="inside"
    echo "$label"
}
show_label
echo "$label"
inside
outside

The local label hides the outer variable during the call.
The outer value is available again when the function finishes.

Builtins: shell and process control

Builtin Use
cd, pwd Change / report the current directory
history Display command history
exec Replace the shell with another program
exit End the current shell
kill Send a signal
trap Arrange a response to a signal or shell event

exec ls replaces the current shell with ls. trap can associate a command with a named signal, such as QUIT. Signal numbers can vary between platforms.

Builtins: data and parameters

Builtin Use
declare, readonly, local Define variable attributes or scope
export, set Manage the environment / shell settings
echo, read Print output / read input
let, test Arithmetic / condition tests
shift Discard leading positional parameters
return End a function and report its status

set with no arguments prints shell variables and functions. shift 2 discards $1 and $2, then renumbers the remaining arguments.

Reading a small script

#!/bin/bash
for filename in "$@"; do
    if [ -f "$filename" ]; then
        wc -l "$filename"
    fi
done

For each argument that names a regular file, print its line count.

Optional: bash -n and -x

bash -n count-lines.sh
bash -x count-lines.sh notes.txt
  • -n: check the syntax without running the script.
  • -x: run the script and print each expanded command on stderr.

-n checks syntax without testing files or running commands. -x shows expanded arguments, which may include private data. Useful test cases include no argument, an empty file, a missing file and a filename containing spaces.
