Storage for 100 integers

size_t count = 100;
int *p = malloc(count * sizeof *p);
if (p == NULL) {

malloc returns the block’s address, or NULL on failure. The contents are uninitialised.

End the allocation's lifetime

Pass the start address of a live allocation from malloc, calloc or realloc. free returns no value.

Count elements, request bytes

void *malloc(size_t size);   // From <stdlib.h>
int *p = malloc(100 * sizeof *p);
  • size_t is unsigned, with at least 16 value bits.
  • sizeof is an operator giving a size in bytes.
  • sizeof *p is the size of one int, not the pointer.

Sizes depend on the platform. In C, the void * result needs no cast.

Where does the program keep its data?

A typical layout, not a C language guarantee. Not to scale.

13–16 min. Show the diagram after students have compiled and used malloc/free. Locate the local count and pointer p in the active stack frame, and the allocated integer block on the heap. The pointer and its target are distinct objects. Calls grow the stack downward in this typical model; allocations occupy heap storage growing upward. Separate allocations need not be adjacent; real allocators may use other mappings. The layout is not a C guarantee.

Who controls an object’s lifetime?

Static storage

Globals and static objects exist for the whole program. Storage is reserved before execution.

Automatic storage

An ordinary local exists during its block execution. Each recursive call gets its own locals.

The implementation manages their storage. Deep recursion can exhaust the stack.

Download C example ↓

16–20 min. Compare three lifetimes only after the allocation example: globals/static objects last for the program; ordinary locals last for their block/call; the heap block lasts until free. Example 14 is optional supporting code for static versus automatic storage, not the lecture opening. Storage for static objects is prepared before execution. Recursive calls get distinct locals and can exhaust stack space; C implementations may also offer variable-length automatic arrays. Padding and layout affect frame storage, and separate heap allocations have no adjacency guarantee.

Four functions in <stdlib.h>

Function Purpose
malloc(bytes) Allocate uninitialised storage
calloc(count, size) Allocate storage with all bits zero
realloc(p, bytes) Resize an allocation; it may move
free(p) Release an allocation

20–22 min. Summarize the API after the working malloc/free program. Original overview only, not a new calloc/realloc lesson. For a nonzero request, realloc failure leaves the old block valid; assign through a temporary pointer. calloc sets all bits to zero, which is not a universal guarantee for pointer/floating representations.
